# Changelog

## 3.8.0 (2026-11-01)

No colour in the palette changed; two of them changed roles.

- Rust and orange trade places between the themes. Structure, the keywords and landmarks, gets the stronger of the two warm colours against the background: rust in Høstlys, as before, and orange in Høstkveld, where rust was. Values, the numbers, constants and parameters, get the other. Rust is the darker of the two in both themes, so it has the most contrast on the light background and the least on the dark one. The terminal colours are unchanged: the slots hold the hues, so yellow is orange and cyan is rust in both presets.
- `\section`, `\subsection` and the other sectioning commands are landmarks in the structure colour, bold, like `\begin` and `\end`. Red is kept for references (`\ref`, `\cite`, links) and errors.
- Decorators stay one plum unit with Pylance. Pylance marks the name after `@` by what it is (`property` as a class, `dataclass` as a function) with the modifier *decorator*, which made the name green once Pylance had loaded; the semantic rules now follow the modifier.
- `docs/rules.md`, `docs/palette.md` and the README describe the roles as structure and values rather than by colour name.

## 3.7.0 (2026-10-31)

- Operators and relations in maths keep the text colour, like `+` and `-`: `=`, `<`, `>`, `|`, `\cdot`, `\times`, `\pm`, `\leq`, `\neq`, `\approx`, `\to`, `\Rightarrow`, `\in`, `\cup`, `\ldots` and the rest of that family. LaTeX Workshop marks only `+ - * / ^ _` as operators, so `=` had the maths colour while the same `=` in tikz options had the text colour, and it gives the commands the same scope as Greek letters, so they were plum; a fifth small injection grammar sorts both out. Greek letters, `\infty`, `\partial`, `\nabla` and the big operators `\sum`, `\prod` and `\int` stay plum, since they stand for a quantity or an operation on one, not for the glue between two.
- The README shows the role of each colour as a card, with the colour in both themes (`docs/roles.svg`, generated by `build.py`).

## 3.6.0 (2026-10-30)

The colours follow written rules, the same in every language, described in [docs/rules.md](https://github.com/dagmortensj/hoest-theme/blob/main/docs/rules.md). No colour in the palette changed; what changed is which words get them.

- Definitions are bold in every language, as `def` and `class` already were in Python. `import`, `export`, `from`, `new` and `#include` are no longer bold.
- Parameters in function signatures are orange and italic, and `self`, `cls` and `this` are plum and italic. Italic marks a placeholder, as variables are set in mathematics. Generic type parameters and `#1` in LaTeX macros are italic too.
- Built-in types such as `int`, `str`, `number` and `double` are green, like built-in functions. CSS properties and HTML attributes are green as well.
- Plum is kept for what you named yourself and for symbols: your classes and types, keys, selectors, decorators as one unit, and special characters in strings, now including placeholders such as `%d`.
- Classes the language provides (`Error`, `Promise`, `ValueError`), special methods such as `__init__` where they are defined, and attributes in JSX are green. Rust attributes such as `#[derive(Debug)]` are plum as one unit, like decorators.
- Logical operators written as symbols (`&&`, `||`, `!`, `??`) keep the text colour like other operators; the words `and`, `or`, `not`, `in` and `is` stay bold. `typeof`, `instanceof`, `satisfies` and `import type` are no longer bold, and constructors, `@mixin` and `@function` are.
- Keys in TOML, attributes in XML, media features in CSS, data types in SQL, enum members in C#, decorators in TypeScript, attributes in C++ and PHP, and `self` in Swift follow the same rules as in the other languages.
- Fixes: types in Go, C#, PHP and Java no longer appear in the keyword colour, the exponent of a number is orange, `new` in C# is no longer bold, and namespaces, package names, package paths in Java and columns in SQL keep the text colour.

## 3.5.1 (2026-10-30)

- A new icon: three leaves in orange, rust and green on the Høstkveld background, drawn from the palette by `src/icon.py`.

## 3.5.0 (2026-10-30)

- The extension is now called `hoest-theme`, matching the repository. VS Code treats it as a new extension, so uninstall the old one first: `code --uninstall-extension dagmorten.host-theme`.
- The status bar button appears only while Høstlys or Høstkveld is active, and works without the `workbench.preferred…ColorTheme` settings. It is also available in the command palette as **Høst: Switch between Høstlys and Høstkveld**.
- An icon for the extension.
- The build script reports every colour that lies outside sRGB and stops if a palette change pushes a new one outside without a decision. No colours changed because of this.
